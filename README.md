# رادار المنتجات الرابحة: منصة Node.js

## التشغيل
```bash
npm install
cp .env.example .env      # عدّل JWT_SECRET و ADMIN_EMAIL
npm start                 # http://localhost:3000
```
يتطلب Node 20.6 أو أحدث. قاعدة البيانات SQLite في ملف `data.db` (انسخه احتياطياً). سجّل أولاً بالبريد الموجود في `ADMIN_EMAIL` ليصبح حسابك مديراً.

## النشر
شغّل الخادم خلف Nginx أو Caddy مع HTTPS، وأبقه حياً بـ PM2 أو systemd. اضبط `NODE_ENV=production` ليعمل الكوكي بوضع secure.

## الاشتراكات
المسجَّل الجديد بلا اشتراك (إلا إذا ضبطت `TRIAL_DAYS`). من «إدارة المشتركين» أضف أياماً لكل عضو بعد استلام دفعه. الحساب المنتهي يرى رسالة تجديد فقط.

## الإضافة 1: مكتبة الإعلانات (واجهة الإرسال)
أضف إلى الإضافة الجاهزة طلباً واحداً بعد جمع الإعلانات، والمفتاح من صفحة «الإضافات والتكامل»:
```js
await fetch(SERVER + '/api/ext/adlib', {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-api-key': API_KEY },
  body: JSON.stringify({ label: keyword, rows: ads })   // ads: مصفوفة بنفس حقول الملف الحالي
});
```
الحقول المقبولة هي نفسها التي يفهمها المحلل: `body, title, link_url, page_name, start_date, status, format, ...`. إن كان الإرسال من content script داخل facebook.com فالأفضل تمريره عبر background script. يسمح الخادم أيضاً بأصل `https://www.facebook.com` (متغير `EXT_ORIGINS`).

## الواجهة البرمجية
| المسار | الوصف |
|---|---|
| `POST /api/ext/adlib` | `{label, rows[]}` من الإضافة 1 |

كل مسارات `/api/ext` تقبل ترويسة `x-api-key`.

## الاستضافة المشتركة (cPanel / Namecheap Stellar Plus)
اضبط المتغيرات من واجهة Setup Node.js App (لا من .env)، وملف البدء `server.js`، واختر Node 22. لا حاجة لـ pm2 أو Caddy. إن فشل تثبيت `better-sqlite3` يعمل الخادم تلقائياً بمحرك `node:sqlite` المدمج.

## الإصدار 6.1: «جمع الإعلانات» داخل المنصة
الجمع من مكتبة إعلانات ميتا صار **قسماً داخل المنصة** («جمع الإعلانات»)، وبقيت في Chrome **إضافة** صغيرة (`extensions/ad-collector`) تفعل الجزء الذي لا يستطيعه موقع: فتح مكتبة ميتا وتمريرها والتقاط الإعلانات، ثم تسلّمها لحسابك.

### التدفق
1. **جمع الإعلانات ← الجمع:** بحث سريع، أو بحث جماعي (كلمات ذهبية × مكمّلات النيشات)، أو جمع الصفحة المفتوحة. «نشطة فقط» هو الافتراضي.
2. تصل الإعلانات **مباشرة إلى «الإعلانات الواردة»** (دفعة لكل عملية جمع، وتكبر لحظة بلحظة دون إعادة تحميل).
3. من «الواردة» تحلّل بمحرك المنصة ومعاييره. **لا تقييم ولا وسم ولا تصفية عند الجمع**: كل التصنيف والتصفية في التحليل.

### الأقسام
- **الجمع:** إعدادات البحث، وضع الإرسال (تلقائي/يدوي)، التقدّم المباشر وبطاقة الإنجاز.
- **القاموس:** كلمات البحث (الذهبية والمكمّلات). الافتراضي (قاموس الإكستنشن القديم مدموجاً مع قاموس المنصة) + تعديلات كل مستخدم تُحفظ كفروقات فلا تضيع عند تحديث الافتراضي. المدير يعدّل الافتراضي للجميع.
- **الإضافة:** التنزيل والتثبيت وحالة الاتصال. تظهر للمدير فقط الدومينات المرتبطة وإرشادات الخادم.

### نافذة الإضافة (أيقونتها في Chrome)
بطاقة تعرض الحالة: جاهزة / جارٍ الجمع / انتهى، رقم البحث الحالي، **المرصود** و**المُرسَل** و**بانتظار الإرسال**، وقائمة عمليات البحث. وفيها:
- **وضع الإرسال:** تلقائي (يصل فور الرصد) أو يدوي (يبقى في الإضافة حتى «إرسال الآن»).
- أزرار: إرسال الآن، تخطّي البحث الحالي، إيقاف، مسح غير المرسل، فتح المنصة.
- لا تعرض أي دومين أو معلومة حساسة.

### التخزين والاحتفاظ
- الإعلانات المجمَّعة صفوف في «الواردة» (جدول `runs`). حدّ الدفعة `LIB_MAX_ADS_PER_BATCH` (5000).
- الدفعات التي **لم تُحلَّل** تُحذف تلقائياً بعد `LIB_RETENTION_DAYS` (45) يوماً. ما حُلِّل يبقى في الأرشيف.
- حماية الحساب: `LIB_MAX_SEARCHES_PER_BATCH` (15) و`LIB_MAX_SEARCHES_PER_DAY` (60) و`LIB_MAX_ADS_PER_SEARCH` (300)، وسرعة عادية أو بطيئة. تُفرض في المنصة وفي الإضافة نفسها. شروط ميتا تقيّد الجمع الآلي ويتحمل المستخدم تبعته.
- ترحيل تلقائي: مكتبة النسخة 6.0 (إن وُجدت) تتحول عند أول تشغيل إلى دفعة في «الواردة».

### توزيع الإضافة
- تُنزَّل من «جمع الإعلانات ← الإضافة» (`/api/lib/extension.zip`، لمشترك فعّال فقط) وتُولَّد عند التنزيل فتُربط بالدومين الذي يفتح منه المشترك المنصة (+ www/بدونها + `BRIDGE_ORIGINS` إن ضُبط). لا تعمل مع أي موقع آخر ولا تحمل مفاتيح.
- عند تحديثها ارفع `version` في `extensions/ad-collector/manifest.json`، و`LIB_BRIDGE_MIN_VERSION` يمنع الجمع بالنسخ الأقدم.
- تتطلب Chrome 116+ على الحاسوب، ويبقى تبويب فيسبوك ظاهراً أثناء الجمع.

### الروابط وأمان الصفحات
لكل قسم رابطه: `/collect` `/collect/dictionary` `/collect/extension` `/inbox` `/analyze` `/archive` `/saved` `/gaps` `/settings` `/subscribers`. صفحات الدخول: `/login` `/register` `/forgot` و`/reset?t=…`. ملفات الواجهة في `views/` (خارج المجلد العام)، فلا تُكشف بأسمائها `.html`. كل ردود `/api` بلا تخزين مؤقت.

### الواجهة البرمجية (بجلسة المستخدم)
`POST /api/lib/ingest` · `GET /api/lib/stats` · `POST /api/lib/batch|tick` · `GET|PUT /api/lib/dict` · `GET /api/lib/extension.zip` · للمدير: `GET|PUT /api/admin/lib/dict` و`POST /api/admin/lib/dict/reset`. الإضافة القديمة `POST /api/ext/adlib` ما زالت تعمل.

### الاختبارات
`npm test` (الخادم والإضافة). اختبار الواجهة في jsdom: `npm i jsdom` خارج المشروع ثم `NODE_PATH=<مسار>/node_modules node adlib/ui-test.js`. لإعادة توليد القاموس الافتراضي: `npm run build:dict`.

## الإصدار 7.0: البحث الدولي الدقيق
كان البحث خارج الجزائر يرسل كلمات عربية وفرنسية وأرابيزي إلى مكتبة ميتا مهما كانت الدولة، ولم يكن هناك أي فحص يميّز المنتج المادي عن الخدمة أو الدورة أو المحل، ولا يُقرأ السعر إلا بالدينار. لذلك امتلأت النتائج الدولية بإعلانات عشوائية.

### ما تغيّر
- **الدول ولغاتها** (`adlib/lib/markets.js`): 50 دولة، لكل دولة لغات البحث الخاصة بها. مثلاً فرنسا بالفرنسية، والولايات المتحدة بالإنجليزية (والإسبانية)، والهند بالإنجليزية والهنغلش، وباكستان بالإنجليزية والأردية، والفلبين بالإنجليزية والتاغالوغ، وتايوان بالصينية التقليدية، وفيتنام بالفيتنامية، وإندونيسيا بالإندونيسية، وإسبانيا بالإسبانية. الجزائر بقيت كما هي: الفصحى والدارجة والفرنسية والأرابيزي.
- **كلمات ذهبية ومكمّلة محلية** لـ 14 لغة جديدة: عبارات يستعملها المعلنون فعلاً في كل سوق، وليست ترجمة حرفية. أمثلة: Helps / your child، Ayuda a / tu bebé، Giúp / bé، 幫助 / 寶寶، Atasi / si kecil. تظهر في «القاموس»، ويستطيع كل مستخدم إضافة كلماته أو تعطيلها، ويستطيع المدير تعديل الافتراضي.
- **ثلاثة أوضاع بحث مستقلة**: الذهبية وحدها، والمكمّلة وحدها، والذهبية + المكمّلة. الترتيب ثابت دائماً: الذهبية أولاً ثم المكمّلة («Helps your child»)، ولم يعد خيار عكس الترتيب موجوداً. في الصينية والتايلاندية تُلصق العبارة المطابقة بلا مسافة.
- **لغة المحتوى «تلقائي»**: تضبط فلتر لغة مكتبة ميتا على لغة الكلمة المبحوث بها.
- **فحص صلاحية المنتج** (`adlib/lib/productcheck.js`) قبل الحفظ، ثم مرة ثانية في التحليل. يزن الأدلة ولا يكتفي بكلمة واحدة: نص الإعلان بلغات السوق، واسم الصفحة، وتصنيفها في فيسبوك، ونوع الزر (CTA)، ونطاق الرابط (متجر التطبيقات، Eventbrite، Udemy، رابط خرائط…)، والسعر بالعملة المحلية، وعبارات «توصيل مجاني / الدفع عند الاستلام / اطلب الآن» المحلية. يُستبعد:
  - الخدمات، والدورات والمحاضرات، والفعاليات والمعارض، والمحلات والفروع الفعلية، والشركات والتوظيف والجمعيات، والتطبيقات والاستثمار، والإعلان الذي لا يحدد منتجاً.
  - المنتجات الغذائية، والكبيرة الحجم، والهشة. السياق يُحترم: «قالب كيك» و«غطاء كنبة» و«زجاج حماية مقوّى» منتجات مقبولة.
  - الإعلان لا يُرفض إلا إذا كانت أدلة «ليس منتجاً» واضحة وأقوى من أدلة المنتج. منتج يقول «زوروا متجرنا» مع سعر وزر شراء يبقى.
- **في الجمع**: خيار «🛡️ فحص صلاحية المنتج قبل الحفظ» مفعّل افتراضياً. تعرض بطاقة التقدّم عدد المستبعد وسببه مع أمثلة. يستطيع المستخدم تعطيله.
- **في التحليل**: المنتج الذي نصف إعلاناته أو أكثر غير صالح يُنقل إلى «مقصاة» مع السبب. ينطبق هذا أيضاً على الملفات المرفوعة والدفعات القديمة. السعر يُقرأ بكل العملات ($ € £ ₹ Rs ₱ NT$ đ Rp ฿ …)، والفائدة تُقرأ بلغات الأسواق كلها.
- **أعمدة جديدة في كل صف**: `country`، `cta_type`، `page_categories`.

## الإصدار 8.0: ثغرات السوق الجزائري
حُذف قسم «أدوات التجسس» نهائياً: القسم، وإضافته (`extensions/spy-extension`)، ومساراه `/api/ext/seeds` و`/api/ext/spy`، ونتائجه القديمة في الأرشيف. الرابط `/spy` يحوّل إلى `/gaps`.

### الفكرة
منتج رابح في سوق أجنبي (من «المنتجات المحفوظة»): هل يُعلَن عنه في الجزائر؟ إن لم يكن، فهو **ثغرة**.

### طريقة العمل
1. في «المنتجات المحفوظة» اضغط **🎯 افحص في الجزائر** على المنتج، فينتقل إلى القسم مع صوره ورابط مورّده ونصوص إعلاناته.
2. **عبارات البحث الجزائرية**: الاسم بالعربية والفرنسية والدارجة، وعبارة بالفائدة.
   - زر **✨ اقتراح بالذكاء الاصطناعي** يملأ العبارات و«الكلمات المميزة» إن ضُبط `OPENAI_API_KEY`. اختيارياً: `OPENAI_MODEL` و`OPENAI_BASE_URL`. إن تعذّر نموذج يُجرَّب التالي.
   - بدون مفتاح تكتب العبارات بنفسك.
3. **الفحص**: الإضافة نفسها تبحث في مكتبة إعلانات ميتا (الجزائر، النشطة والمتوقفة) بكل عبارة. الصفحة تقارن كل إعلان لحظة وصوله، ولا تذهب هذه الإعلانات إلى «الواردة». المقارنة (`adlib/lib/gapmatch.js`):
   - **بصمة الصورة** (dHash على الصورة كاملة و90% و80% من وسطها): تتعرّف على صورة المورّد حتى لو صُغّرت أو أُطّرت أو أُضيف عليها شعار.
   - **رابط المورّد**: نفس رقم المنتج على AliExpress / Temu / Amazon / Alibaba / SHEIN / CJ / 1688.
   - **الكلمات المميزة**: دليل مساعد فقط. لا تُحتسب كلمات العبارة التي أعادت الإعلان.
   - النتيجة: ✅ مؤكد (صورة أو رابط) أو ❔ محتمل يعرض بجانب صورة المنتج لتقرر «نفس المنتج / ليس هو».
4. **الحكم**:
   - 🟢 ثغرة مؤكدة: لا شيء بعد اكتمال بحثين على الأقل.
   - 🟡 منافسة ضعيفة: بائع أو بائعان نشطان.
   - 🔵 جُرّب وتوقف: إعلانات متوقفة فقط.
   - 🔴 مشبع: 3 بائعين نشطين فأكثر.
   - 🟠 يحتاج تحققك.
   - ⚪ غير حاسم.
5. **المراقبة الأسبوعية**: كل منتج مفحوص يُستحق لإعادة الفحص بعد 7 أيام (يمكن إيقافها لكل منتج). تظهر شارة على القائمة، وزر «افحص المستحق تباعاً» يفحصها واحداً بعد الآخر. يحتاج الفحص الإضافة والمتصفح مفتوحين، لأن مكتبة ميتا لا تُقرأ من الخادم.

الفحص يستهلك من حدّ عمليات البحث اليومي نفسه (حماية حساب فيسبوك).

## الإصدار 11.2: الفائدة، «واعد»، والإقصاء الخاطئ
- **التصنيفات**: 0–3 أيام 🧪 تحت التجربة · 4–7 🌱 **واعد** (بشروط الجوهرة: فائدة + قلة بائعين أو نسختان) · 8–30 💎 جوهرة · 31–60 🔥 رابح · 🔸 رابح محتمل · قديم · ضعيف · مقصاة.
  الترتيب بنفس هذا التسلسل. الأيام 4–7 تأخذ نصف نقاط المدة («اجتاز التجربة الأولى»).
- **الفائدة** = فعل ذهبي + مشكلة/نتيجة خلال 4 كلمات («يقضي على الناموس»، «يحمي هاتفك من الكسر»)، أو صيغة اسمية + مشكلة («مضاد للتعرق»، «بدون ألم»، «وداعاً للبقع»، anti, sans, no more).
  الأفعال العامة (يساعد، يحمي، يوفر…) لا تُحتسب بلا مشكلة، و«نساعدك في التوصيل/الطلب/المقاس» ليست فائدة.
- **الإقصاء الخاطئ**: حُذفت قاعدة «كلمة واحدة في أي مكان» للهش وكبير الحجم؛ يحكم فحص الصلاحية (موازنة أدلة + استثناء الإكسسوارات).
  الكلمات التي تتغير بالهمزة تُطابق حرفياً («مرآة» ≠ «المرأة»). سبب الإقصاء يُظهر الجملة الأصلية، وزر **↩️ سبب خاطئ** يعيد المنتج ويحفظ التصحيح (في التحليل وعند الاستقبال)، والتراجع من «إعدادات التحليل».
- اختبار جديد: `node adlib/criteria-e2e-test.js`.

## الإصدار 11.3: المدة والفائدة فقط
- **إصلاح «URI malformed»** عند تحليل دفعة أو فتح نتيجة: نص قُطع في منتصف إيموجي كان يُسقط إنشاء الروابط. يُنظَّف الآن عند القراءة وعند الحفظ، والترميز في الصفحة لا يسقط.
- **التصنيف بالمدة وحدها**: 0–3 تحت التجربة · 4–7 واعد · 8–30 جوهرة · 31–60 رابح · 61+ قديم · ⏹️ توقف بعد نجاح · ضعيف (بلا تاريخ) · مقصاة.
- **الفائدة للترتيب فقط** داخل كل تصنيف: ✅ فائدة (العنوان/أول النص) ← ☑️ فائدة في النص (باقي النص) ← بلا فائدة واضحة. ثم الأكثر رصداً نشطاً في أيام الجمع (المتابعة)، ثم الأطول عمراً.
- **حُذفت**: عدد البائعين، عدد النسخ، المنتجات المشابهة، اتجاه السوق، النقاط من 100، «رابح محتمل»، وفلاتر «أدنى درجة/أقصى بائعين».
- **الإقصاء**: صفحة العلامة الرسمية، وما ليس منتجاً (خدمة، دورة، فعالية، محل، شركة، تطبيق). **الهش/الكبير/الأكل: وسم تنبيه فقط** «⚠️ قد يكون…».
- **⏹️ توقف بعد نجاح**: كل إعلانات المنتج متوقفة لكن أحدها استمر 8 أيام فأكثر (فرصة لسوق آخر). ما توقف قبل ذلك يُقصى.

## الإصدار 11.4: أرقام صفحة التحليل، النسخ والبائعون
- **الأرقام الستة** أعلى صفحة التحليل (كل إعلان وكل منتج يُعد مرة واحدة):
  الإعلانات المرصودة (ما تعرضه مكتبة ميتا «~220 نتيجة»، تقرؤه الإضافة 1.5) · التي تم جلبها (بلا تكرار) · دخلت التحليل · المستبعدة (عند الاستقبال + في التحليل + متوقفة) · عدد المنتجات · عدد البائعين.
  المجلوب = دخلت التحليل + المستبعدة. أُصلح خطأ «نشط 271 / متوقف ‎-61» (كان يعد المنتج الظاهر في تصنيفين مرتين).
- **البطاقة**: «نسخ» (مجموع «X إعلانات تستخدم هذا التصميم» من ميتا، مرة لكل مجموعة) و«بائعين» (صفحات/متاجر مختلفة) كمعلومة فقط، لا تؤثر في التصنيف ولا الترتيب.
- حُذف وسم «فائدة / بلا فائدة»؛ الفائدة تبقى للترتيب فقط.
- **الإضافة 1.5.0** (يجب إعادة تثبيتها لظهور «الإعلانات المرصودة»).

## الإصدار 11.5
- **الإعلانات المرصودة**: الإضافة 1.6.0 تقرأ «~220 نتيجة» من نص الصفحة أيضاً (علامات الاتجاه المخفية، الأرقام العربية، الفواصل، كل اللغات)، وترسل العدد في نهاية كل بحث حتى لو لم يبقَ إعلان للإرسال.
- **بطاقة واحدة لكل منتج**: تصنيفه = عمر أقدم إعلان نشط له، وأعمار نسخه الأخرى في «له نسخ أيضاً في». فصار «الكل» = عدد المنتجات = مجموع التبويبات.
- حُذف تصنيف «توقف بعد نجاح»: المنتج الذي كل إعلاناته متوقفة يُستبعد.

## الإصدار 11.6: أرقام دقيقة بلا تناقض
- **بلا تجميع**: كل إعلان بطاقة بتصنيف عمره (التحليل نفسه: المدة ثم الفائدة للترتيب).
- **«الكل» = الإعلانات التي تم جلبها = مجموع التبويبات**، والإعلانات المستبعدة عند الاستقبال تظهر في تبويب **🚫 مستبعد** بسببها.
- أعلى الصفحة: المرصودة · التي تم جلبها · دخلت التحليل · المستبعدة · **عدد البائعين (أسماء صفحات مختلفة)**.
- حُذف: عدد النسخ، عدد المنتجات، وأرقام النسخ والبائعين من البطاقة.

## الإصدار 11.7
- **الواردة = ما أرسلته الإضافة**: العدد يشمل المستبعدة عند الوصول («217، منها 3 مستبعدة»).
- **لا تصنيف «ضعيف»**: الإعلان بلا تاريخ بدء يُستبعد مع وسم سببه.
- **TikTok**: رابط البحث بنفس صيغة البحث اليدوي (`…/search?q=…&t=<الوقت>`).
- **الإضافة 1.7.0**: تعرض «مرصود في ميتا: N» مباشرة أثناء الجمع (أو «لم يُقرأ عدد ميتا بعد») لمعرفة هل قُرئ العدد.
