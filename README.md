# رادار المنتجات الرابحة: منصة Node.js

## التشغيل
```bash
npm install
cp .env.example .env      # عدّل JWT_SECRET و ADMIN_EMAIL
npm start                 # http://localhost:3000
```
يتطلب Node 20.6 أو أحدث. قاعدة البيانات SQLite في ملف `data.db` (انسخه احتياطياً). سجّل أولاً بالبريد الموجود في `ADMIN_EMAIL` ليصبح حسابك مديراً.

## النشر
شغّل الخادم خلف Nginx أو Caddy مع HTTPS، وأبقه حياً بـ PM2 أو systemd. اضبط `NODE_ENV=production` ليعمل الكوكي بوضع secure.

## الاشتراكات
المسجَّل الجديد بلا اشتراك (إلا إذا ضبطت `TRIAL_DAYS`). من «إدارة المشتركين» أضف أياماً لكل عضو بعد استلام دفعه. الحساب المنتهي يرى رسالة تجديد فقط.

## الإضافة 1: مكتبة الإعلانات (واجهة الإرسال)
أضف إلى الإضافة الجاهزة طلباً واحداً بعد جمع الإعلانات، والمفتاح من صفحة «الإضافات والتكامل»:
```js
await fetch(SERVER + '/api/ext/adlib', {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-api-key': API_KEY },
  body: JSON.stringify({ label: keyword, rows: ads })   // ads: مصفوفة بنفس حقول الملف الحالي
});
```
الحقول المقبولة هي نفسها التي يفهمها المحلل: `body, title, link_url, page_name, start_date, status, format, ...`. إن كان الإرسال من content script داخل facebook.com فالأفضل تمريره عبر background script. يسمح الخادم أيضاً بأصل `https://www.facebook.com` (متغير `EXT_ORIGINS`).

## الواجهة البرمجية
| المسار | الوصف |
|---|---|
| `POST /api/ext/adlib` | `{label, rows[]}` من الإضافة 1 |

كل مسارات `/api/ext` تقبل ترويسة `x-api-key`.

## الاستضافة المشتركة (cPanel / Namecheap Stellar Plus)
اضبط المتغيرات من واجهة Setup Node.js App (لا من .env)، وملف البدء `server.js`، واختر Node 22. لا حاجة لـ pm2 أو Caddy. إن فشل تثبيت `better-sqlite3` يعمل الخادم تلقائياً بمحرك `node:sqlite` المدمج.

## الإصدار 6.1: «جمع الإعلانات» داخل المنصة
الجمع من مكتبة إعلانات ميتا صار **قسماً داخل المنصة** («جمع الإعلانات»)، وبقيت في Chrome **إضافة** صغيرة (`extensions/ad-collector`) تفعل الجزء الذي لا يستطيعه موقع: فتح مكتبة ميتا وتمريرها والتقاط الإعلانات، ثم تسلّمها لحسابك.

### التدفق
1. **جمع الإعلانات ← الجمع:** بحث سريع، أو بحث جماعي (كلمات ذهبية × مكمّلات النيشات)، أو جمع الصفحة المفتوحة. «نشطة فقط» هو الافتراضي.
2. تصل الإعلانات **مباشرة إلى «الإعلانات الواردة»** (دفعة لكل عملية جمع، وتكبر لحظة بلحظة دون إعادة تحميل).
3. من «الواردة» تحلّل بمحرك المنصة ومعاييره. **لا تقييم ولا وسم ولا تصفية عند الجمع**: كل التصنيف والتصفية في التحليل.

### الأقسام
- **الجمع:** إعدادات البحث، وضع الإرسال (تلقائي/يدوي)، التقدّم المباشر وبطاقة الإنجاز.
- **القاموس:** كلمات البحث (الذهبية والمكمّلات). الافتراضي (قاموس الإكستنشن القديم مدموجاً مع قاموس المنصة) + تعديلات كل مستخدم تُحفظ كفروقات فلا تضيع عند تحديث الافتراضي. المدير يعدّل الافتراضي للجميع.
- **الإضافة:** التنزيل والتثبيت وحالة الاتصال. تظهر للمدير فقط الدومينات المرتبطة وإرشادات الخادم.

### نافذة الإضافة (أيقونتها في Chrome)
بطاقة تعرض الحالة: جاهزة / جارٍ الجمع / انتهى، رقم البحث الحالي، **المرصود** و**المُرسَل** و**بانتظار الإرسال**، وقائمة عمليات البحث. وفيها:
- **وضع الإرسال:** تلقائي (يصل فور الرصد) أو يدوي (يبقى في الإضافة حتى «إرسال الآن»).
- أزرار: إرسال الآن، تخطّي البحث الحالي، إيقاف، مسح غير المرسل، فتح المنصة.
- لا تعرض أي دومين أو معلومة حساسة.

### التخزين والاحتفاظ
- الإعلانات المجمَّعة صفوف في «الواردة» (جدول `runs`). حدّ الدفعة `LIB_MAX_ADS_PER_BATCH` (5000).
- الدفعات التي **لم تُحلَّل** تُحذف تلقائياً بعد `LIB_RETENTION_DAYS` (45) يوماً. ما حُلِّل يبقى في الأرشيف.
- حماية الحساب: `LIB_MAX_SEARCHES_PER_BATCH` (15) و`LIB_MAX_SEARCHES_PER_DAY` (60) و`LIB_MAX_ADS_PER_SEARCH` (300)، وسرعة عادية أو بطيئة. تُفرض في المنصة وفي الإضافة نفسها. شروط ميتا تقيّد الجمع الآلي ويتحمل المستخدم تبعته.
- ترحيل تلقائي: مكتبة النسخة 6.0 (إن وُجدت) تتحول عند أول تشغيل إلى دفعة في «الواردة».

### توزيع الإضافة
- تُنزَّل من «جمع الإعلانات ← الإضافة» (`/api/lib/extension.zip`، لمشترك فعّال فقط) وتُولَّد عند التنزيل فتُربط بالدومين الذي يفتح منه المشترك المنصة (+ www/بدونها + `BRIDGE_ORIGINS` إن ضُبط). لا تعمل مع أي موقع آخر ولا تحمل مفاتيح.
- عند تحديثها ارفع `version` في `extensions/ad-collector/manifest.json`، و`LIB_BRIDGE_MIN_VERSION` يمنع الجمع بالنسخ الأقدم.
- تتطلب Chrome 116+ على الحاسوب، ويبقى تبويب فيسبوك ظاهراً أثناء الجمع.

### الروابط وأمان الصفحات
لكل قسم رابطه: `/collect` `/collect/dictionary` `/collect/extension` `/inbox` `/analyze` `/archive` `/saved` `/gaps` `/settings` `/subscribers`. صفحات الدخول: `/login` `/register` `/forgot` و`/reset?t=…`. ملفات الواجهة في `views/` (خارج المجلد العام)، فلا تُكشف بأسمائها `.html`. كل ردود `/api` بلا تخزين مؤقت.

### الواجهة البرمجية (بجلسة المستخدم)
`POST /api/lib/ingest` · `GET /api/lib/stats` · `POST /api/lib/batch|tick` · `GET|PUT /api/lib/dict` · `GET /api/lib/extension.zip` · للمدير: `GET|PUT /api/admin/lib/dict` و`POST /api/admin/lib/dict/reset`. الإضافة القديمة `POST /api/ext/adlib` ما زالت تعمل.

### الاختبارات
`npm test` (الخادم والإضافة). اختبار الواجهة في jsdom: `npm i jsdom` خارج المشروع ثم `NODE_PATH=<مسار>/node_modules node adlib/ui-test.js`. لإعادة توليد القاموس الافتراضي: `npm run build:dict`.

## الإصدار 7.0: البحث الدولي الدقيق
كان البحث خارج الجزائر يرسل كلمات عربية وفرنسية وأرابيزي إلى مكتبة ميتا مهما كانت الدولة، ولم يكن هناك أي فحص يميّز المنتج المادي عن الخدمة أو الدورة أو المحل، ولا يُقرأ السعر إلا بالدينار. لذلك امتلأت النتائج الدولية بإعلانات عشوائية.

### ما تغيّر
- **الدول ولغاتها** (`adlib/lib/markets.js`): 50 دولة، لكل دولة لغات البحث الخاصة بها. مثلاً فرنسا بالفرنسية، والولايات المتحدة بالإنجليزية (والإسبانية)، والهند بالإنجليزية والهنغلش، وباكستان بالإنجليزية والأردية، والفلبين بالإنجليزية والتاغالوغ، وتايوان بالصينية التقليدية، وفيتنام بالفيتنامية، وإندونيسيا بالإندونيسية، وإسبانيا بالإسبانية. الجزائر بقيت كما هي: الفصحى والدارجة والفرنسية والأرابيزي.
- **كلمات ذهبية ومكمّلة محلية** لـ 14 لغة جديدة: عبارات يستعملها المعلنون فعلاً في كل سوق، وليست ترجمة حرفية. أمثلة: Helps / your child، Ayuda a / tu bebé، Giúp / bé، 幫助 / 寶寶، Atasi / si kecil. تظهر في «القاموس»، ويستطيع كل مستخدم إضافة كلماته أو تعطيلها، ويستطيع المدير تعديل الافتراضي.
- **ثلاثة أوضاع بحث مستقلة**: الذهبية وحدها، والمكمّلة وحدها، والذهبية + المكمّلة. الترتيب ثابت دائماً: الذهبية أولاً ثم المكمّلة («Helps your child»)، ولم يعد خيار عكس الترتيب موجوداً. في الصينية والتايلاندية تُلصق العبارة المطابقة بلا مسافة.
- **لغة المحتوى «تلقائي»**: تضبط فلتر لغة مكتبة ميتا على لغة الكلمة المبحوث بها.
- **فحص صلاحية المنتج** (`adlib/lib/productcheck.js`) قبل الحفظ، ثم مرة ثانية في التحليل. يزن الأدلة ولا يكتفي بكلمة واحدة: نص الإعلان بلغات السوق، واسم الصفحة، وتصنيفها في فيسبوك، ونوع الزر (CTA)، ونطاق الرابط (متجر التطبيقات، Eventbrite، Udemy، رابط خرائط…)، والسعر بالعملة المحلية، وعبارات «توصيل مجاني / الدفع عند الاستلام / اطلب الآن» المحلية. يُستبعد:
  - الخدمات، والدورات والمحاضرات، والفعاليات والمعارض، والمحلات والفروع الفعلية، والشركات والتوظيف والجمعيات، والتطبيقات والاستثمار، والإعلان الذي لا يحدد منتجاً.
  - المنتجات الغذائية، والكبيرة الحجم، والهشة. السياق يُحترم: «قالب كيك» و«غطاء كنبة» و«زجاج حماية مقوّى» منتجات مقبولة.
  - الإعلان لا يُرفض إلا إذا كانت أدلة «ليس منتجاً» واضحة وأقوى من أدلة المنتج. منتج يقول «زوروا متجرنا» مع سعر وزر شراء يبقى.
- **في الجمع**: خيار «🛡️ فحص صلاحية المنتج قبل الحفظ» مفعّل افتراضياً. تعرض بطاقة التقدّم عدد المستبعد وسببه مع أمثلة. يستطيع المستخدم تعطيله.
- **في التحليل**: المنتج الذي نصف إعلاناته أو أكثر غير صالح يُنقل إلى «مقصاة» مع السبب. ينطبق هذا أيضاً على الملفات المرفوعة والدفعات القديمة. السعر يُقرأ بكل العملات ($ € £ ₹ Rs ₱ NT$ đ Rp ฿ …)، والفائدة تُقرأ بلغات الأسواق كلها.
- **أعمدة جديدة في كل صف**: `country`، `cta_type`، `page_categories`.

## الإصدار 8.0: ثغرات السوق الجزائري
حُذف قسم «أدوات التجسس» نهائياً: القسم، وإضافته (`extensions/spy-extension`)، ومساراه `/api/ext/seeds` و`/api/ext/spy`، ونتائجه القديمة في الأرشيف. الرابط `/spy` يحوّل إلى `/gaps`.

### الفكرة
منتج رابح في سوق أجنبي (من «المنتجات المحفوظة»): هل يُعلَن عنه في الجزائر؟ إن لم يكن، فهو **ثغرة**.

### طريقة العمل
1. في «المنتجات المحفوظة» اضغط **🎯 افحص في الجزائر** على المنتج، فينتقل إلى القسم مع صوره ورابط مورّده ونصوص إعلاناته.
2. **عبارات البحث الجزائرية**: الاسم بالعربية والفرنسية والدارجة، وعبارة بالفائدة.
   - زر **✨ اقتراح بالذكاء الاصطناعي** يملأ العبارات و«الكلمات المميزة» إن ضُبط `OPENAI_API_KEY`. اختيارياً: `OPENAI_MODEL` و`OPENAI_BASE_URL`. إن تعذّر نموذج يُجرَّب التالي.
   - بدون مفتاح تكتب العبارات بنفسك.
3. **الفحص**: الإضافة نفسها تبحث في مكتبة إعلانات ميتا (الجزائر، النشطة والمتوقفة) بكل عبارة. الصفحة تقارن كل إعلان لحظة وصوله، ولا تذهب هذه الإعلانات إلى «الواردة». المقارنة (`adlib/lib/gapmatch.js`):
   - **بصمة الصورة** (dHash على الصورة كاملة و90% و80% من وسطها): تتعرّف على صورة المورّد حتى لو صُغّرت أو أُطّرت أو أُضيف عليها شعار.
   - **رابط المورّد**: نفس رقم المنتج على AliExpress / Temu / Amazon / Alibaba / SHEIN / CJ / 1688.
   - **الكلمات المميزة**: دليل مساعد فقط. لا تُحتسب كلمات العبارة التي أعادت الإعلان.
   - النتيجة: ✅ مؤكد (صورة أو رابط) أو ❔ محتمل يعرض بجانب صورة المنتج لتقرر «نفس المنتج / ليس هو».
4. **الحكم**:
   - 🟢 ثغرة مؤكدة: لا شيء بعد اكتمال بحثين على الأقل.
   - 🟡 منافسة ضعيفة: بائع أو بائعان نشطان.
   - 🔵 جُرّب وتوقف: إعلانات متوقفة فقط.
   - 🔴 مشبع: 3 بائعين نشطين فأكثر.
   - 🟠 يحتاج تحققك.
   - ⚪ غير حاسم.
5. **المراقبة الأسبوعية**: كل منتج مفحوص يُستحق لإعادة الفحص بعد 7 أيام (يمكن إيقافها لكل منتج). تظهر شارة على القائمة، وزر «افحص المستحق تباعاً» يفحصها واحداً بعد الآخر. يحتاج الفحص الإضافة والمتصفح مفتوحين، لأن مكتبة ميتا لا تُقرأ من الخادم.

الفحص يستهلك من حدّ عمليات البحث اليومي نفسه (حماية حساب فيسبوك).

## الإصدار 11.2: الفائدة، «واعد»، والإقصاء الخاطئ
- **التصنيفات**: 0–3 أيام 🧪 تحت التجربة · 4–7 🌱 **واعد** (بشروط الجوهرة: فائدة + قلة بائعين أو نسختان) · 8–30 💎 جوهرة · 31–60 🔥 رابح · 🔸 رابح محتمل · قديم · ضعيف · مقصاة.
  الترتيب بنفس هذا التسلسل. الأيام 4–7 تأخذ نصف نقاط المدة («اجتاز التجربة الأولى»).
- **الفائدة** = فعل ذهبي + مشكلة/نتيجة خلال 4 كلمات («يقضي على الناموس»، «يحمي هاتفك من الكسر»)، أو صيغة اسمية + مشكلة («مضاد للتعرق»، «بدون ألم»، «وداعاً للبقع»، anti, sans, no more).
  الأفعال العامة (يساعد، يحمي، يوفر…) لا تُحتسب بلا مشكلة، و«نساعدك في التوصيل/الطلب/المقاس» ليست فائدة.
- **الإقصاء الخاطئ**: حُذفت قاعدة «كلمة واحدة في أي مكان» للهش وكبير الحجم؛ يحكم فحص الصلاحية (موازنة أدلة + استثناء الإكسسوارات).
  الكلمات التي تتغير بالهمزة تُطابق حرفياً («مرآة» ≠ «المرأة»). سبب الإقصاء يُظهر الجملة الأصلية، وزر **↩️ سبب خاطئ** يعيد المنتج ويحفظ التصحيح (في التحليل وعند الاستقبال)، والتراجع من «إعدادات التحليل».
- اختبار جديد: `node adlib/criteria-e2e-test.js`.

## الإصدار 11.3: المدة والفائدة فقط
- **إصلاح «URI malformed»** عند تحليل دفعة أو فتح نتيجة: نص قُطع في منتصف إيموجي كان يُسقط إنشاء الروابط. يُنظَّف الآن عند القراءة وعند الحفظ، والترميز في الصفحة لا يسقط.
- **التصنيف بالمدة وحدها**: 0–3 تحت التجربة · 4–7 واعد · 8–30 جوهرة · 31–60 رابح · 61+ قديم · ⏹️ توقف بعد نجاح · ضعيف (بلا تاريخ) · مقصاة.
- **الفائدة للترتيب فقط** داخل كل تصنيف: ✅ فائدة (العنوان/أول النص) ← ☑️ فائدة في النص (باقي النص) ← بلا فائدة واضحة. ثم الأكثر رصداً نشطاً في أيام الجمع (المتابعة)، ثم الأطول عمراً.
- **حُذفت**: عدد البائعين، عدد النسخ، المنتجات المشابهة، اتجاه السوق، النقاط من 100، «رابح محتمل»، وفلاتر «أدنى درجة/أقصى بائعين».
- **الإقصاء**: صفحة العلامة الرسمية، وما ليس منتجاً (خدمة، دورة، فعالية، محل، شركة، تطبيق). **الهش/الكبير/الأكل: وسم تنبيه فقط** «⚠️ قد يكون…».
- **⏹️ توقف بعد نجاح**: كل إعلانات المنتج متوقفة لكن أحدها استمر 8 أيام فأكثر (فرصة لسوق آخر). ما توقف قبل ذلك يُقصى.

## الإصدار 11.4: أرقام صفحة التحليل، النسخ والبائعون
- **الأرقام الستة** أعلى صفحة التحليل (كل إعلان وكل منتج يُعد مرة واحدة):
  الإعلانات المرصودة (ما تعرضه مكتبة ميتا «~220 نتيجة»، تقرؤه الإضافة 1.5) · التي تم جلبها (بلا تكرار) · دخلت التحليل · المستبعدة (عند الاستقبال + في التحليل + متوقفة) · عدد المنتجات · عدد البائعين.
  المجلوب = دخلت التحليل + المستبعدة. أُصلح خطأ «نشط 271 / متوقف ‎-61» (كان يعد المنتج الظاهر في تصنيفين مرتين).
- **البطاقة**: «نسخ» (مجموع «X إعلانات تستخدم هذا التصميم» من ميتا، مرة لكل مجموعة) و«بائعين» (صفحات/متاجر مختلفة) كمعلومة فقط، لا تؤثر في التصنيف ولا الترتيب.
- حُذف وسم «فائدة / بلا فائدة»؛ الفائدة تبقى للترتيب فقط.
- **الإضافة 1.5.0** (يجب إعادة تثبيتها لظهور «الإعلانات المرصودة»).

## الإصدار 11.5
- **الإعلانات المرصودة**: الإضافة 1.6.0 تقرأ «~220 نتيجة» من نص الصفحة أيضاً (علامات الاتجاه المخفية، الأرقام العربية، الفواصل، كل اللغات)، وترسل العدد في نهاية كل بحث حتى لو لم يبقَ إعلان للإرسال.
- **بطاقة واحدة لكل منتج**: تصنيفه = عمر أقدم إعلان نشط له، وأعمار نسخه الأخرى في «له نسخ أيضاً في». فصار «الكل» = عدد المنتجات = مجموع التبويبات.
- حُذف تصنيف «توقف بعد نجاح»: المنتج الذي كل إعلاناته متوقفة يُستبعد.

## الإصدار 11.6: أرقام دقيقة بلا تناقض
- **بلا تجميع**: كل إعلان بطاقة بتصنيف عمره (التحليل نفسه: المدة ثم الفائدة للترتيب).
- **«الكل» = الإعلانات التي تم جلبها = مجموع التبويبات**، والإعلانات المستبعدة عند الاستقبال تظهر في تبويب **🚫 مستبعد** بسببها.
- أعلى الصفحة: المرصودة · التي تم جلبها · دخلت التحليل · المستبعدة · **عدد البائعين (أسماء صفحات مختلفة)**.
- حُذف: عدد النسخ، عدد المنتجات، وأرقام النسخ والبائعين من البطاقة.

- **الإدارة مقسّمة** (مجموعة «الإدارة» في القائمة، للمدير فقط): نظرة عامة (`/admin`) · المشتركون (`/subscribers`) · العروض والمدفوعات (`/payments`: طلبات الدفع، العروض والمميزات، طرق الدفع) · صندوق الدعم (`/support-inbox`) · إعدادات المنصة (`/platform`: النشاط والتواصل، الذكاء الاصطناعي، التنبيهات، الصفحات القانونية، النسخ الاحتياطي، سجل الأخطاء). مفاتيح المنصة خرجت من «الربط والتكامل» (صار للمشترك فقط). شارات لطلبات الدفع والرسائل الجديدة.
- **مركز المساعدة**: بحث في الأسئلة، 14 سؤالاً مصنّفة، بطاقات (الدليل، واتساب، راسل الدعم)، نموذج بنوع الطلب، و**«طلباتي»** بحالة كل طلب وردّ الدعم. المدير **يردّ من المنصة** فيصل الرد للمشترك مع تنبيه.
- **البداية في مكان واحد**: الخطوات الخمس أعلى «دليل الاستخدام»، ولوحة التحكم تعرض شريط تقدّم مختصراً فقط (حُذف «إظهار دليل البداية» المكرر).
- **لوحة التحكم**: ملخص الفترة (اليوم / 7 أيام / 30 يوماً / الكل) وتنبيهات قابلة للضغط: دفعات بانتظار التحليل، منتجات مستحقة لإعادة الفحص، قرب انتهاء الاشتراك، الاقتراب من حد العرض (80%)، رد الدعم.
- **تنبيه 80%** من حد العرض في بطاقة الاشتراك أيضاً.
- اختيار اللغة من الزر العائم فقط (حُذفت القوائم المكررة في الصفحات العامة).

## الإصدار 13.2: أمان الحساب، عروض أوضح، بلا تكرار
- **أمان الحساب** (`/security`، مستوحى من فايدة نت): حالة الحماية في الأعلى، **التحقق بخطوتين** بتطبيق مصادقة (رمز QR + مفتاح يدوي، 8 رموز استرجاع لمرة واحدة، إيقاف بكلمة المرور + الرمز)، تغيير كلمة المرور، الأجهزة وعمليات الدخول وتنبيه المحاولات الفاشلة. صفحة الدخول تطلب الرمز بعد كلمة المرور. تنبيه في لوحة التحكم ما دام غير مفعّل. `adlib/totp.js` (RFC 6238 بلا مكتبات)، `public/qrcode.js` (MIT).
- **قائمة الحساب**: الملف الشخصي (`/settings`) · اشتراكي (`/subscription`، ورجوع الدفع إليها) · أمان الحساب · تسجيل الخروج. «الإعدادات» الشخصية لم تعد تشبه «إعدادات المنصة» (للمدير)، و«اشتراكي» لا يُخلط بـ«العروض والمدفوعات» (للمدير).
- **محرّر العروض**: بطاقة عمودية لكل عرض (الاسم والحالة، السعر والمدة، الحدود، المميزات، الشارة) بدل الجدول الأفقي.
- حذف «خطواتك الأولى» المكررة؛ لوحة التحكم تعرض للمستخدم الجديد بطاقة واحدة نحو «مسار العمل».
- **تحليل الإعلان بالذكاء الاصطناعي** لسوق المشترك المستهدف (العرض المقترح، الملاءمة، ونصوص الإعلان بلغات ذلك السوق).
- عنوان الأسعار في الصفحة الرئيسية: «ابدأ مجاناً، ثم اختر الباقة التي تناسبك» + عنوان فرعي وشارة «تجربة مجانية · بلا بطاقة بنكية».
- إصلاح رسالة الخطأ «W.WPRACC.admin is not a function» في قسم المشتركين.
- اختبار جديد: `adlib/security-2fa-test.js` (19 فحصاً).

## الإصدار 13.11: البحث بصورة المنتج في كل سوق، إعلانات مشابهة في «ثغرات السوق»، وإصلاح تمدد الصفحة
- **تمدد الصفحة**: كان «التلميح» العائم يبقى مخفياً في أسفل آخر صفحة طويلة مررت عليها، فتطول الصفحة التالية بفراغ أبيض وينزاح الشريط الجانبي. صار التلميح ثابتاً على الشاشة فلا يطيل أي صفحة.
- **🖼️ البحث بصورة المنتج** (نافذة المورّد + بطاقة كل منتج): زر لكل سوق: 1688، AliExpress، Alibaba، Taobao، Pinduoduo. مع الإضافة 1.7.4 تفتح الإضافة السوق وترفع صورة المنتج في «البحث بالصورة» تلقائياً؛ إن لم تجد الزر (مثلاً يطلب تسجيل الدخول) تضع الصورة في أعلى صفحة السوق لترفعها بنفسك. بدون الإضافة: يُفتح السوق وتُنزَّل الصورة. Pinduoduo لا يتيح البحث بالصورة إلا في تطبيقه، فتُنزَّل الصورة مع الشرح. بقي البحث بالكلمة وGoogle Lens وYandex كما هي.
- **الأسواق الصينية**: تنبيه عندما تكون عبارة 1688/Taobao/Pinduoduo غير صينية (مع رابط ترجمة Google)، وتوضيح أن Pinduoduo وTaobao يطلبان تسجيل الدخول (Pinduoduo برقم هاتف) — هذا من الموقع الرسمي نفسه وليس خطأ في التوجيه.
- **ثغرات السوق**: إن لم يطابق أي إعلان، تظهر نتائج البحث نفسها كـ«إعلانات مشابهة» مرتبة من الأقرب (الصورة + كلمات المنتج)، وزر «نفس المنتج» يحسبها منافساً. لا تغيّر الحكم إلا إن أكدتها. تُبنى من جديد مع كل فحص (أقصى 40).
- اختبار جديد `adlib/imgsearch-e2e-test.js`: الإضافة الحقيقية محمّلة في Chromium مع صفحات أسواق محاكاة.

## الإصدار 13.10: واجهة أكثر حياة، بطاقة منتجات جديدة، والمدد 3/6/12
- **بطاقة المنتجات في الواجهة**: صارت نافذة مصغّرة من المنصة: شريط عنوان، «منتجات رابحة اليوم» مع مؤشر «مباشر»، أرقام سريعة، وصفوف بأيقونة ومنحنى نموّ صغير وشارة ملوّنة هادئة (بدل المربعات الملونة وأشرطة التقدّم).
- **الحركة**: الأزرار ترتفع قليلاً عند المرور، البطاقات تتحرك بلطف، الأقسام تظهر تدريجياً عند النزول، الصفحات والنوافذ تظهر بانسياب. تُلغى كلها لمن فعّل «تقليل الحركة».
- **المساعدة والدعم**: البطاقات الثلاث (الدليل، الدفع والاشتراك ← واتساب، رسالة مكتوبة ← النموذج)، ثم قسما «تحدّث معنا على واتساب» و«رسالة مكتوبة» برأس موحّد وعنوان بلون المنصة.
- **المدد**: 3 و6 و12 شهراً فقط (حُذف «شهر»؛ التجربة المجانية هي البداية). **الباقات القديمة** (شهري/ربع سنوي/سنوي) تُحذف نهائياً، ومن كان عليها يُنقل إلى «الأساسية» بنفس تاريخ انتهائه.
- حذف شيفرة وأنماط لم تعد مستعملة (بقايا الإعداد الأولي القديم وغيرها).

## الإصدار 13.9: تنظيم الاشتراك والمساعدة، أسماء الباقات، وواجهة بيضاء
- **أسماء الباقات**: الأساسية، المتقدمة، الاحترافية (الأسعار وطريقة الحساب بالمدد كما في 13.8). قاعدة بيانات 13.8 تُعاد تسميتها تلقائياً مع المشتركين ومدفوعاتهم.
- **«اشتراكي»**: قسم «الدفع والتجديد» رأسه زر «الدفع أو تغيير العرض» بلون المنصة، وتحته خيارات واتساب كقائمة منظمة (بدل الصندوق الأخضر).
- **«المساعدة والدعم»**: بلا تكرار: البطاقتان (الدليل، الدفع والاشتراك ← تنزل إلى واتساب) ← قسم واتساب بكل المواضيع ← رسالة مكتوبة ← طلباتي ← الأسئلة. حُذف «(بديل واتساب)».
- **واجهة بيضاء**: الخلفية والبطاقات بيضاء بحدود خفيفة (كانت رمادية مخضرّة)، في كل الصفحات.
- **عنوان الأسعار** بلون العناوين العادي، وكلمة «مجاناً» بالأخضر.

## الإصدار 13.8: أسعار بالمدد، إحصائيات شاملة، ووضع الصيانة
- **الأسعار مثل فايدة نت**: كل باقة بسعر شهري (البداية 3900، النمو 6900، الاحتراف 10900 دج)، والمشترك يختار المدة: شهر، 3 أشهر (−5٪)، 6 أشهر (−8٪)، 12 شهراً (−15٪).
  6 أشهر بالمبالغ المعتمدة: 21.500 / 38.000 / 60.100 دج (3.583 / 6.333 / 10.017 للشهر). صفحة الأسعار بأزرار المدد وبطاقات (السعر الشهري، المجموع، التوفير)،
  والتجربة المجانية شريط فوقها (يذكر ما ليس مشمولاً فيها). نافذة الدفع: المدة ← الباقة ← طريقة الدفع، وكل بوابات الدفع ورسائل واتساب بمبلغ المدة.
  المدير يعدّل المدد والخصومات، والسعر الشهري، ومبلغاً يدوياً لكل مدة (فارغ = تلقائي؛ المبلغ اليدوي الأعلى من السعر الكامل يُهمَل). الباقات القديمة (شهري/ربع سنوي/سنوي) تُعطَّل مرة واحدة وتبقى للسجل.
  التفعيل اليدوي لمشترك: اختيار الباقة والمدة.
- **إصلاح حفظ المميزات**: كان في صفحة الباقات زرّان («حفظ الباقات» و«حفظ المميزات») فيضيع تعديل أحدهما؛ صار زر واحد «حفظ كل التغييرات».
- **إحصائيات شاملة** (`adlib/stats.js`، «نظرة عامة»): المتصلون الآن، يدفع/تجربة/منتهٍ، التسجيلات 30 يوماً، نسبة التحويل، النشطون اليوم/الأسبوع، البلدان (من المنطقة الزمنية ولغة المتصفح، بلا خدمة خارجية)،
  لغة الواجهة، الأسواق المستهدفة، الإيرادات (شهرياً، حسب الطريقة، حسب المدة، المنتظر)، كل ما يجري (الإعلانات المجلوبة، البحث، الذكاء الاصطناعي، الثغرات، المراقبة، TikTok، الدعم، التنبيهات)،
  الإعلانات حسب السوق، أنشط المشتركين، والنظام (الإصدار، الذاكرة، حجم القاعدة، آخر نسخة احتياطية، الأخطاء، الصيانة).
- **وضع الصيانة** (إعدادات المنصة ← وضع الصيانة): الزوار والمشتركون يرون صفحة «نُحسّن المنصة الآن» بلغتهم مع موعد العودة وزر واتساب (503)، والمدير يعمل عادياً مع شريط تنبيه.
  صفحة الدخول والصفحات القانونية وإشعارات بوابات الدفع تبقى تعمل، والصفحة تعود تلقائياً عند الإيقاف.

## الإصدار 13.7: واتساب أولاً، إشعارات أهدأ، وفحص شامل
- **رسائل واتساب جاهزة يضبطها المدير** (إعدادات المنصة ← رسائل واتساب، `adlib/wa.js`): وصل الدفع، ترقية/تغيير العرض، التجديد، سؤال عن الدفع، طلب مساعدة،
  بثلاث لغات مع متغيرات `{plan} {amount} {store} {email}…`. المشترك يجدها في «اشتراكي» وفي «المساعدة والدعم»: يختار الموقف، تظهر الرسالة بمعلومات حسابه
  (يعدّلها إن أراد) ثم تُفتح في واتساب. «وصل الدفع» يسجّل طلب الدفع للمدير أولاً ويضع رقمه في الرسالة.
- **واتساب هو قناة التواصل الأساسية**: في المساعدة (في الأعلى، والرسالة المكتوبة بديل)، في «اتصل بنا»، ورابط «تواصل مع الإدارة»، وبطاقة الاشتراك المنتهي (جدّد عبر واتساب).
- **الإشعارات**: نفس الرسالة لا تتكرر عند الضغط المتكرر، 3 على الأكثر، تختفي بعد 2.6 ث (الخطأ 5 ث)، والضغط عليها يغلقها.
- **فحص شامل** (`adlib/audit-e2e-test.js` ضمن الاختبارات): كل الأقسام كمدير ومشترك ومشترك منتهٍ، بثلاث لغات: لا أخطاء، لا طلبات فاشلة، لا نص غير مترجم، لا تداخل صلاحيات.
  أُصلح: المشترك كان يستطيع فتح صفحات المدير برابطها المباشر (البيانات كانت محمية من الخادم، والواجهة الآن أيضاً)؛ «الخروج من المنافسة» صار تابعاً لميزة الذكاء الاصطناعي في الباقة؛
  نصوص قديمة تشير إلى «الإعدادات ← الاشتراك»؛ نصوص غير مترجمة؛ حذف شيفرة لم تعد مستعملة.

## الإصدار 13.6: مراقبة منافسين أوضح، وحل شهادة البريد
- **مراقبة المنافسين**: كل صفحة بطاقة بثلاثة أرقام (نشط الآن، جديد في آخر فحص، توقف في آخر فحص) وجملة واضحة عن آخر فحص والفحص القادم.
  داخل الصفحة **سجل الفحوص**: الفحص الأول = نقطة البداية (ما كان موجوداً قبل المراقبة، لا يُعدّ جديداً)، ثم كل فحص بعده: +جديد / توقف / نشط،
  مع زر لعرض إعلانات ذلك الفحص بالضبط. كل إعلان يذكر الفحص الذي ظهر فيه والذي توقف فيه. (جدول `watch_scans` يحفظ الآن `added` و `gone` و `stats`.)
- **البريد على الاستضافة المشتركة (Namecheap)**: شهادة خادم البريد باسم الاستضافة (`web-hosting.com`) لا باسم الدومين، فيفشل الإرسال بخطأ altnames.
  صار البريد التجريبي يقترح اسم الشهادة الصحيح بزر «اعتمد اسم الشهادة وأعد التجربة» (يُحفظ في الإعدادات، أو `SMTP_TLS_SERVERNAME=web-hosting.com` في .env).
  الشهادة تبقى موثّقة من جهة إصدارها؛ يتغير فقط الاسم الذي تُطابَق به.

## الإصدار 13.5: «الخروج من المنافسة» بالذكاء الاصطناعي، وتشخيص البريد
- **قسم جديد «الخروج من المنافسة»** (`/compete`، في القائمة تحت «منتجاتي»، وزر «اخرج من المنافسة» في كل بطاقة منتج):
  منتج رابح يبيعه كثيرون ← يدرس الذكاء الاصطناعي المنتج (صورته ووصفه) ونصوص إعلانات المنافسين، ثم يعطي:
  حالة المنافسة وما يقوله كل المنافسين، والمساحات التي لا يستعملها أحد، و10–12 فكرة مرتّبة من 13 نوعاً
  (باك مع منتجات مكمّلة، خيار إضافي، تفكيك وبيع الأجزاء، شريحة جديدة، زاوية جديدة، مناسبة/هدية، هيكلة العرض، تغليف وتخصيص،
  خدمة مضافة، البيع للمحترفين، شكل/حجم جديد، محتوى مختلف، فكرة غير متوقعة)، لكل فكرة: ماذا تبيع بالضبط، لماذا تُخرجك من المنافسة،
  السعر، كيف تختبرها في أيام بميزانية صغيرة، المخاطر، افتتاحية إعلان بلغة السوق؛ ثم أفضل 3 أفكار وخطة اختبار لـ 7 أيام.
  زر «أفكار أخرى» يعطي أفكاراً جديدة غير السابقة. لا يخترع مواصفات أو مراجعات، ويكتب الافتراضات التي تحتاج تحققاً من المورّد.
  يعمل في الخلفية (`adlib/edge.js`، جدول `edge_runs`) فلا ينقطع الطلب الطويل على الاستضافة، والطلب الفاشل لا يُحتسب من الرصيد.
- **البريد**: الخطأ لم يعد مخفياً. في «إعدادات المنصة ← تيليغرام والبريد»: آخر محاولة إرسال (نجحت أو فشلت ولماذا مع الحل)،
  بريد تجريبي إلى أي عنوان (مثلاً Gmail)، وفحص إعدادات الدومين (MX، SPF، DKIM، DMARC). الرسائل صارت بنسخة نصية أيضاً وبعنوان رد.
- أيقونة المتصفح (favicon) صارت نفس شعار الرادار.

## الإصدار 13.4: أيقونات احترافية وفوتر أنظف
- كل الإيموجي في واجهة المنصة (🧠 💎 🔥 🌱 📡 …) صارت أيقونات خطية موحّدة بلون النص (`public/icons.js`، بأسلوب Lucide)، في الواجهة واللوحة وصفحات الدخول والصفحات القانونية. نص المستخدم (الإعلانات وأسماء المنتجات) لا يُلمس.
- مربعات المنتجات في الواجهة وصفحة الدخول صارت بأيقونة تدل على المنتج (منزل ذكي، سيارة، منتج عناية).
- روابط الفوتر في صف أفقي، ومسافة أقل تحت سطر الحقوق.

## الإصدار 13.3: لمسات الواجهة والبريد
- **استعادة كلمة المرور**: إصلاح «L is not defined» في نموذج «نسيت كلمة المرور». المنصة تقرأ `MAIL_FROM` (أو `SMTP_FROM`). زر **«إرسال بريد تجريبي إلى بريدك»** في «إعدادات المنصة ← التنبيهات» يُظهر سبب الفشل بالضبط (شهادة/كلمة مرور/منفذ). أخطاء إرسال الاستعادة تُسجَّل في «سجل الأخطاء». خيارات `SMTP_TLS_SERVERNAME` و `SMTP_TLS_INSECURE` للاستضافة المشتركة. أزرار البريد خضراء.
- **لوحة التحكم**: حُذف تنبيه «فعّل التحقق بخطوتين» (الحماية في «أمان الحساب»).
- **الصفحة الرئيسية**: اللغة في الأعلى (زر 🌐 بقائمة)، والأزرار العائمة واتساب والوضع فقط. فوتر جديد: الشعار والاسم والوصف، القائمة، والحقوق في الوسط أسفل، بمسافة لا تغطيها الأزرار العائمة. سطر الدفع صار جملة («ادفع بسهولة عبر BaridiMob أو CCP أو تحويل بنكي…، وفريق الدعم معك عبر واتساب»). النص ينسب العمل للمنصة لا للإضافة.

## قائمة التشغيل الفعلي (قبل الإطلاق)
1. **الدومين و HTTPS**: وجّه الدومين للخادم، وفعّل شهادة SSL (cPanel ← SSL/TLS Status ← AutoSSL، أو Caddy/Certbot على VPS).
2. **ملف `.env`**: `NODE_ENV=production` (لتأمين ملف الدخول)، `JWT_SECRET` عشوائي طويل (`openssl rand -hex 32`) **لا يتغير بعد الإطلاق** (تغييره يُخرج الجميع ويُبطل المفاتيح المحفوظة)، `ADMIN_EMAIL` بريدك، `APP_URL=https://دومينك`.
3. **البريد (SMTP)**: من cPanel أنشئ بريد `no-reply@دومينك` واضبط `SMTP_HOST/PORT/USER/PASS/FROM`، ثم جرّب «نسيت كلمة المرور».
4. **النسخ الاحتياطي**: اضبط `BACKUP_DIR` على مجلد خارج مجلد التطبيق، وحمّل نسخة من تبويب «النسخ الاحتياطي» مرة أسبوعياً إلى جهازك.
5. **المراقبة**: أنشئ حساباً مجانياً في UptimeRobot وأضف مراقبة HTTP(s) على `https://دومينك/api/health` كل 5 دقائق مع تنبيه بالبريد/تيليغرام.
6. **من «الربط والتكامل»**: معلومات النشاط والدعم، بوابات الدفع (ابدأ بوضع test ثم live بعد دفعة تجريبية حقيقية)، بوت تيليغرام، مفتاح OpenAI، معرّفات القياس.
7. **الباقات**: الأسعار والمميزات وأيام التجربة من «المشتركون ← الباقات».
8. **حزمة متجر Chrome**: `npm run build:store -- دومينك` ثم ارفع `store-build/chrome-store-package.zip`.
